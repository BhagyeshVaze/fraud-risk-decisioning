**FLAG RAISED: median transactions per account is 1.0.**

Reporting this because it is the tripwire condition, but the tripwire is measuring the wrong population here. The median *account* has 1 transaction because 57.5% of accounts are cards seen exactly once in the 182-day window, which is ordinary for card data. The median *transaction*, which is what the window features actually operate on, sits in an account of 5. 78.8% of transactions belong to accounts with more than one transaction, so the proxy is grouping. Verdict: not a defect, but the 21.2% of transactions in singleton accounts will never have prior-window history and the model must tolerate that.

## Part 3: the decision layer

### Cost assumptions

These are **assumptions, not measured facts**. IEEE-CIS contains no chargeback, margin, or churn data, so these are plausible mid-market card-not-present values chosen to make the tradeoff explicit. Every dollar figure below inherits their uncertainty.

```
{
  "chargeback_fee_usd": 25.0,
  "margin_rate": 0.025,
  "churn_prob_after_false_decline": 0.05,
  "account_lifetime_value_usd": 200.0,
  "manual_review_cost_usd": 2.0
}
```

Cost model, applied per transaction:

| Outcome | Cost |
| --- | --- |
| fraud approved (FN) | transaction amount + $25 chargeback fee |
| legit declined (FP) | 2.5% margin lost + 5% x $200 churn + $2 review |
| fraud declined (TP) | $2 review |
| legit approved (TN) | $0 |
